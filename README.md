# ML-Based PID Auto-Tuner for DC Motor



## 1. Project Overview



This project develops a simulation-based PID auto-tuning system for a DC motor. It evaluates different Proportional (Kp), Integral (Ki), and Derivative (Kd) controller gains and measures the resulting motor response.



The generated dataset can be used by the machine-learning component to investigate relationships between controller parameters and motor performance.



## 2. Project Objectives



- Simulate the response of a DC motor.

- Implement a PID controller.

- Calculate motor-response performance metrics.

- Generate a dataset using different PID gain combinations.

- Validate and rank the generated configurations.

- Prepare the dataset and documentation for the machine-learning component.

## 7. PID Controller



The PID controller uses three gains:



- **Kp â€” Proportional gain:** Responds to the current control error.

- **Ki â€” Integral gain:** Responds to accumulated error.

- **Kd â€” Derivative gain:** Responds to the rate of change of error.



Main script:



`src/pid\_controller.py`



The controller is evaluated by comparing the motor's actual speed with the target speed.



## 8. Performance Metrics



The project evaluates PID configurations using the following metrics:



- **Final speed (RPM):** Motor speed at the end of the simulation.

- **Final error (RPM):** Difference between the target speed and final motor speed.

- **Steady-state error (%):** Final speed error expressed as a percentage of the target speed.

- **Overshoot (%):** Amount by which the response exceeds the target speed.

- **Rise time (s):** Time taken to reach the specified rise-time thresholds.

- **Settling time (s):** Time required for the response to enter and remain within the specified settling band.

- **IAE (RPMÂ·s):** Integral of the absolute speed error over time.



Lower IAE indicates a smaller accumulated absolute tracking error over the evaluated simulation interval.

## 14. Current Limitations



- The dataset uses a single target speed of 100 RPM and one motor simulation setup.

- The 180 configurations vary PID gains rather than motor characteristics.

- Consequently, this dataset alone cannot establish how optimal PID gains change across different motors, loads, or target speeds.

- Missing rise-time and settling-time measurements require careful treatment in downstream analysis.

- Structural validation does not independently verify the physical accuracy of the motor model.



A model intended to recommend gains for different motor conditions will require suitable training examples covering those conditions.

## 18. From-Scratch ML Auto-Tuner (No Third-Party ML Library)

The new ML pipeline implements a small multi-output Decision Tree Regressor in `src/decision_tree.py` using Python's standard library. It does not use scikit-learn, TensorFlow, or a pretrained model. The motor simulator still uses NumPy and Pandas, as the existing project does.

### New files

- `src/generate_motor_dataset.py` — simulates different motor parameter sets, searches candidate gains, and saves all experiments plus the best-found candidate for each motor.
- `src/decision_tree.py` — Decision Tree implementation from scratch.
- `src/train_gain_model.py` — trains the tree and holds out entire motor profiles for testing.
- `src/pid_tuning_utils.py` — shared scoring and simulation-based gain refinement.
- `src/evaluate_unseen_motors.py` — evaluates the model on held-out motors and simulates both raw predictions and refined gains.
- `src/run_auto_tuner.py` — example end-to-end tuning run; edit the motor parameters in this file to test another simulated motor.
- `src/test_decision_tree.py` — basic smoke test for tree training, prediction, and serialization.

### Run the pipeline (from the repository root)

Install the existing simulation dependencies:

```powershell
python -m pip install -r requirements.txt
```

Generate motor-aware data:

```powershell
python src\generate_motor_dataset.py
```

Train the Decision Tree:

```powershell
python src\train_gain_model.py
```

Evaluate on motor profiles excluded from training:

```powershell
python src\evaluate_unseen_motors.py
```

Run the example auto-tuner:

```powershell
python src\run_auto_tuner.py
```

Run the Decision Tree smoke test:

```powershell
python src\test_decision_tree.py
```

### Generated files

- `data/motor_training_data.csv` — candidate gain experiments across simulated motors.
- `data/optimal_pid_dataset.csv` — best-found candidate for each motor in the search.
- `outputs/decision_tree.json` — saved trained model and its train/test motor IDs.
- `outputs/training_report.txt` — training summary.
- `outputs/unseen_motor_results.csv` — held-out motor predictions and simulation metrics before and after refinement.

### Important interpretation

The selected gains are the best candidates found by the finite search, not proven global optima. A small Decision Tree trained on a limited synthetic dataset is a prototype, not proof of generalization to every motor. The raw ML prediction is measured separately from the simulation-based refinement; the latter searches candidate gains in the simulator and selects the best-scoring response. This project is simulation-only and does not establish safe gains for real hardware.

## Expanded motor-aware dataset and unseen-motor evaluation

The motor-aware pipeline samples 200 simulated DC motor profiles and tests 64 PID-gain candidates per motor (4 fixed candidates plus 60 random candidates), producing 12,800 candidate experiments when all simulations are valid.

### Generate the datasets

Run from the repository root:

```powershell
python src\generate_motor_dataset.py
```

Outputs:
- `data/motor_training_data.csv`: candidate experiments for all sampled motors.
- `data/optimal_pid_dataset.csv`: one best-found candidate per motor, selected by the project's composite score.

The selected gains are the best among the candidates tested; they are not guaranteed global optima. Running the generator overwrites these dataset files, so back them up if prior outputs need to be retained.

### Train and evaluate on held-out motors

```powershell
python src\train_gain_model.py
python src\evaluate_unseen_motors.py
```

The training script uses 80% of motor profiles for training and reserves 20% as unseen test motors. The current evaluation reports both raw ML-predicted gains and gains refined using additional simulation-based candidate search. These are different methods and must be reported separately.
